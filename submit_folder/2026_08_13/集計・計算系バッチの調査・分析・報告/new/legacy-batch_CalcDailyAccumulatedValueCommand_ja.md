# 旧バッチ ― CalcDailyAccumulatedValueCommand（日毎積算値データ算出機能）

## 概要

`CalcDailyAccumulatedValueCommand` は旧システム（EMINEL コンシェルジュサーバー）内で**1時間に1回**実行されるバッチである。本バッチは、ガスコージェネレーション（ガス発電電力量）、太陽光発電（太陽光発電電力量）、買電/売電（買電量/売電量）、蓄電池の放電/充電（蓄電池放電量/充電量）、および人感検知回数（時間粒度で再計算）という6種類の機器について、**時間ごとの積算差分**（時間の境界をまたぐ2回の読み取り間の endValue − startValue）を算出する。クラス名に "Daily/日毎" とあるのは、格納先テーブルが「1行＝1日 × 24時間カラム」という構造で保存するためであり、これは保存単位であって、算出単位は「時間」である。

本バッチはDBの読み書きのみを行う ― 外部APIの呼び出し、CSVファイルの読み込み/出力、メール送信は一切行わない。結果は `s_102` に書き込まれ、月次/年次の集計バッチによってさらに集約される。実行スケジュール、機器種別ごとの計算式、および欠損データの補完メカニズムの詳細は第2部に記載する。

## 第1部 ― 概要

| 項目 | 内容 |
|---|---|
| **役割** | ECHONETの**積算**読み取り値から、6種類の機器（ガスコージェネレーション、太陽光発電、買電/売電、蓄電池の放電/充電、および時間粒度で再計算する人感）について**時間ごとの差分**を算出し、各世帯に対応する「日」の行のうち該当する1時間カラムにのみ書き込む。 |
| **Input** | DBの読み取りのみ。**外部API呼び出しなし、CSV読み込みなし**：`t_101`（世帯一覧。コージェネレーション種別/太陽光発電の有無/電力ポイントコードなどの設定を含む）＋ `t_202`（あらかじめ取り込み済みのECHONET機器状態の生データ）。 |
| **Output** | **DBへの書き込みのみ** ― 実行1回につき機器種別ごとに1時間カラムを `s_102`（1行/日 × 24時間カラム）へupsertする。再計算（欠損補完）メカニズムが作動した場合は、同時に複数カラムへ書き込むこともある。メール送信なし、CSV出力なし。 |
| **処理概要** | 1. `--type`（必須）と `--datetime`（任意、デフォルト＝現在時刻の1時間前）を読み込み、バリデーションする。<br>2. 各 `type` について：論理削除されていない世帯一覧を取得する。<br>3. 各世帯について：時間境界の2つのウィンドウ `[T,T+1h)` と `[T+1h,T+2h)` を読み取り、各ウィンドウの最も早いレコードを取得し、機器種別に応じた6通りのhex正規化式のうち1つを適用する。<br>4. 終了値から開始値を引いた差分を計算し、小数点以下4桁で丸める。<br>5. `s_102` の該当する日の行に1時間カラムをupsertする。<br>6. 直前の時間カラムがNULLかどうかを確認する。NULLの場合は、直近のデータが存在する時点まで遡って探索し、空白の時間帯に均等按分して補完する。 |

## 第2部 ― 詳細

### 2.1 実行スケジュールとパラメータ

| 項目 | 内容 |
|---|---|
| 実行スケジュール（cron） | `17 * * * *` ― 1時間に1回、17分に実行 |
| 実行コマンド | `php cake.php CalcDailyAccumulatedValue --type=<...> [--datetime=<...>]` |
| `--type` | 必須 ― カンマ区切りで複数値を指定可能。各値は以下の有効な機器種別グループのいずれかに属する：`GAS_POWER`, `SOLAR_GENERATION`, `SALE_ELECTRIC`, `BATTERY_DISCHARGE`, `DETECT_CNT` |
| `--datetime` のデフォルト | `現在時刻 − 1時間` |
| `--datetime` を手動指定する場合 | フォーマット `yyyy-MM-ddTHH:00:00+09:00` |
| 計算対象ウィンドウ | 開始 = `datetime` ・ 終了 = `datetime + 1h` ・ 該当する時間カラムに書き込む |

`BUY_ELECTRIC` と `BATTERY_CHARGE` は上記の有効な機器種別グループには含まれておらず、`--type` へ直接渡すことはできない ― この2種は `SALE_ELECTRIC`/`BATTERY_DISCHARGE` の拡張要素として間接的にのみ処理される（[2.9](#29-関連する業務定数) を参照）。

### 2.2 対象世帯の選定

各機器種別について処理対象となる世帯一覧は、世帯一覧テーブル（`t_101`）と、以前に書き込まれた時間別値テーブル（`s_102`）を結合することで取得される。

`s_102` とのテーブル結合の結果は、世帯を絞り込むためには使われない ― 返される一覧は**論理削除されていない（有効な）すべての世帯**である。ただし機器種別が `SALE_ELECTRIC`（売電）の場合は、売電機能をオフにしている世帯がさらに除外される。機器種別が `DETECT_CNT`（人感）の場合は、クエリ末尾のグルーピング処理により、部屋を区別しないことで生じ得る重複行が除去される。「この世帯のこの時間にすでに値があるかどうか」は、後続のステップ（計測データの有無に基づく）でのみ判定され、この世帯選定のステップでは判定されない。

### 2.3 6種類の機器と正規化計算式

各機器種別について、バッチは生データから読み取るべき機器クラスコード（EOJ）とプロパティ（EPC）を選定し、hexを実値へ正規化する計算式を適用する。

| `type` | 業務名称 | EOJ（クラス） | 使用するEPC | 計算式 |
|---|---|---|---|---|
| `GAS_POWER`（8） | ガス発電電力量 | `027F%`（コレモ、`customer.c024=1` の場合）または `027C%`（エネファーム、`c024=2` の場合） | `0xC5` | `hexdec(文字列) / 1000` → kWh |
| `SOLAR_GENERATION`（9） | 太陽光発電電力量 | `0279%` | `0xE1` | `hexdec(文字列) / 1000` → kWh |
| `SALE_ELECTRIC`（10） / `BUY_ELECTRIC`（11） | 売電量 / 買電量 | `0288%` | `0xD3,0xD7,0xE0,0xE1,0xE3`（4～5項目を同時に使用） | [2.3.1](#231-sale_electricbuy_electric-の分岐) を参照 |
| `BATTERY_DISCHARGE`（12） | 蓄電池（放電量） | `027D%` | `0xA9` | `hexdec(文字列) / 1000` → kWh |
| `BATTERY_CHARGE`（13） | 蓄電池（充電量） | `027D%`（放電と同じEOJ） | `0xA8` | `hexdec(文字列) / 1000` → kWh |
| `DETECT_LIVING`（0） / `DETECT_OTHER`（1）（`DETECT_CNT`（14）の下位） | 人感検知回数 | `0F45%` | `0xEC` / `0xED` | `hexdec(先頭8文字)` → 回数 |

読み取り方法に関する補足：

- `BATTERY_DISCHARGE`/`BATTERY_CHARGE` は同一のEOJを使用し、1つのクエリで同時に読み取られる ― システムは同じ生データセットに対して差分計算式を2回呼び出す（放電用に1回、充電用に1回）。
- `DETECT_LIVING`/`DETECT_OTHER` は本バッチ内で「時間」粒度の生データから直接読み取られる（同じ指標をより小さい粒度で処理する10分バッチとは独立している）。
- `GAS_POWER` のEOJは、マスタデータ内の世帯のコージェネレーション種別設定に基づいて選定され、計測データから推測されるものではない。

#### 2.3.1 `SALE_ELECTRIC`/`BUY_ELECTRIC` の分岐

この計算式は、生の読み取り値を実際のkWhへ変換するために5つのプロパティ（EPC）を同時に使用する。

```text
coefficient    = hexdec(0xD3)                              # 換算係数、6桁
numberDigits   = hexdec(0xD7)                               # 有効桁数（1～8）
forwardValue   = hexdec(0xE0)                               # 順方向（買電）の計測値
reverseValue   = hexdec(0xE3)                               # 逆方向（売電）の計測値
unit           = 0xE1 のhex値に応じてテーブルを参照          # 例：0x03→0.001、0x0A→10、...

BUY_ELECTRIC  = forwardValue × coefficient × unit    （numberDigits が forwardValue の桁数以上の場合）
```

`SALE_ELECTRIC` については、世帯のマスタデータ（太陽光発電の有無、コージェネレーション種別、電力供給地点の受付コード）に基づく3つの分岐がある。

| 条件 | 結果 |
|---|---|
| 太陽光発電なし **かつ** COREMO種別のコージェネレーションを使用 **かつ** 電力受付地点コードあり | 計算しない、値を書き込まない |
| 太陽光発電あり | `= reverseValue × coefficient × unit`（有効桁数を満たす場合） |
| それ以外 | `= 0` |

コード内のコメントには、1行目の条件について「電力受付地点コードがまだ値を持っていない（NULL）」と書かれているが、実際のコードはその逆をチェックしている ― 電力受付地点コードに**すでに**値がある場合にのみ適用される。

機器種別の設定において、`BUY_ELECTRIC`（買電）は `SALE_ELECTRIC` と同時に実行される機器一覧から除外されている ― 両方を同時に実行する旧設定行はコメントアウトされ、`SALE_ELECTRIC` のみを単独で実行する行だけが残っている。この設定では、計算式自体はコード内に完全な形で残っているものの、バッチは `SALE_ELECTRIC` のみを計算し、`BUY_ELECTRIC` は計算しない。

### 2.4 2つの時間境界ウィンドウ（start/end）の読み取り方法

各世帯・各機器種別について、バッチは生データを2回読み取る。

```text
読み取り1（時間の開始）： [T, T+1h) の範囲で最も早いレコードを取得
読み取り2（時間の終了）： [T+1h, T+2h) の範囲で最も早いレコードを取得
```

ここで `T` は計算対象の時間である（デフォルト＝実行時刻の1時間前）。

```text
「T時の開始値」 = [T, T+1h) の範囲で最も早いレコード
「T時の終了値」 = [T+1h, T+2h) の範囲で最も早いレコード

hourValue(T) = floor((終了値 − 開始値) × 10000) / 10000
```

### 2.5 差分計算式

```text
hourValue = floor((endValue − startValue) × 10000) / 10000
```

`GAS_POWER`/`SOLAR_GENERATION`/`BATTERY_DISCHARGE`/`BATTERY_CHARGE`/`SALE_ELECTRIC`/`BUY_ELECTRIC` について、この計算式には負値を排除するステップが無い ― 負の差分もそのまま計算され、通常の値として `s_102` に書き込まれる。`DETECT_LIVING`/`DETECT_OTHER` については別途チェックがあり、2つの特殊値 `FFFFFFFF`/`FFFFFFFE`（センサー未接続/応答なし）を `null` に変換する。コード内のコメントには有効範囲（`0` ～ `999999999`）外の値も除外する意図が書かれているが、実際の条件は `&&` で自己矛盾しているため一度も作動しない ― 範囲外フィルタは機能していない。このステップでは差分の符号はチェックされない。

### 2.6 「日」テーブル（`s_102`）への1時間カラムの書き込み

`s_102` は4つのカラムからなる複合主キーを持つ：（世帯コード、機器種別、位置、日付）。実行のたびに、バッチは対応する1つの時間カラムのみをセットして保存する ― 常に新しいレコードを作成し主キーに基づいて保存する方式であり、既存の行を読み込んで更新するわけではない。主キーが「日」単位（「時間」単位ではない）であるため、1日あたり24回の実行はすべて同じ行を対象としつつ、毎回異なるカラムをセットすることになる。

`s_102` の各フィールド：

| フィールド | 意味 | セットされるタイミング |
|---|---|---|
| `c001`~`c004` | 主キー（世帯コード、機器種別、位置、日付） | 書き込みのたびに |
| `c008` | 消費電力量の再計算が必要であることを示すフラグ | 新しい値を書き込む場合は `= 1`；人感の欠損補完メカニズム経由で書き込む場合は `= 2` |
| `c009` | 月次への集計が必要であることを示すフラグ | 現在時刻の値を書き込む場合は `= 2`；過去の日付のデータを補完する場合は `= 1` |
| `c111`~`c115` | 5つの属性グループ：住宅種別、暖房熱源（13A/LPG/電気/灯油/その他）、床面積、人数、コージェネレーション種別 | 世帯一覧から各行へコピー |
| `c011`~`c034` | 時間別値24カラム（00時台～23時台） | 実行1回につき1カラム |

### 2.7 直前の時間がNULLの場合の再計算（欠損補完）

現在時刻の値を書き込んだ後、バッチは常に、本日の日付行における直前の時間カラムが空欄（NULL）になっていないかを確認する。空欄である場合は、以下のステップを実行する。

```text
1. 1時間ずつ、1日ずつ遡り、NULLでない値を持つ最も近い時間を探す
   → 以下のいずれかで停止：
     (a) 値のある時間が1つ見つかった場合、または
     (b) s_102 に行が1つも存在しない日に到達した場合
2. 元データから生の積算値の全系列を、
   [見つかった起点, 現在時刻 − 1h] の範囲で読み直す
3. 連続する各空白区間について、平均値を計算する：
   1時間あたりの値 = floor((区間全体の差分) / 空白時間数 × 10000) / 10000
4. その平均値をすべての空白時間に書き込む。
   各レコードも通常の行と同様に、フラグ/属性グループを漏れなくセットする
```

本バッチには、ステップ1の遡り日数を制限する定数は存在しない。

### 2.8 後続の集計チェーン

本バッチは、「1行・時間単位のNカラム」という構造を共有する一連のバッチの最初の連結点である。

```
t_202（生のECHONET、積算値）
   │  CalcDailyAccumulatedValueCommand  （☚ 分析対象のバッチ ― 1時間に1回実行）
   ▼
s_102  "ConSensorHourlyValues"   1行/日   × 24時間カラム（c011~c034）
   │  月次集計バッチ（1日1回実行）
   ▼
s_103  "ConSensorDailyValues"    1行/月  × 31日カラム
   │  年次集計バッチ（1ヶ月に1回実行）
   ▼
s_104  "ConSensorMonthlyValues"  1行/年    × 12ヶ月カラム
```

月次/年次へ集計される機器種別の一覧には `DETECT_CNT`（人感）は含まれない ― 人感は日レベルで止まり、月次/年次へは上がらない。

同系統の別バッチである `CalcDailyEnergyConsumptionCommand` は、本バッチが `s_102` に書き込む5つの時間カラム（type 8, 9, 10, 12, 13：ガス発電、太陽光、蓄電池放電、蓄電池充電、および売電の一部。買電カラム type 11 は別フローが供給する）を入力として読み取り、消費電力量（`消費電力量`）の計算式を組み立てる。計算式の詳細および2つ目の依存バッチ（`RcvHalfHourElectricPowerCommand`。買電/売電の一部の出所）については、同一ドキュメントセット内の `legacy-batch_CalcDailyEnergyConsumption.md` を参照。

### 2.9 関連する業務定数

各主要機器種別は、実行時に計算すべき子機器種別へ展開される：`GAS_POWER`/`SOLAR_GENERATION` は自身のみを計算する；`BATTERY_DISCHARGE` は `BATTERY_CHARGE` も併せて計算する；`DETECT_CNT` は2つの部屋（`DETECT_LIVING`、`DETECT_OTHER`）の両方を計算する；`SALE_ELECTRIC` のみは `BUY_ELECTRIC` へ展開**しない**（[2.3.1](#231-sale_electricbuy_electric-の分岐) を参照）。

| 定数 | 値 |
|---|---|
| `GAS_POWER` / `SOLAR_GENERATION` / `SALE_ELECTRIC` / `BUY_ELECTRIC` / `BATTERY_DISCHARGE` / `BATTERY_CHARGE` / `DETECT_CNT` | `8 / 9 / 10 / 11 / 12 / 13 / 14` |
| `DETECT_LIVING` / `DETECT_OTHER` | `0 / 1` |
| 丸め桁数の上限 | `floor(value × 10000) / 10000` ― 小数点以下4桁 |
| 人感読み取り値の上限しきい値 | `999999999` |
| 電力量の単位 | 単位プロパティ（`0xE1`）のhex値に応じて参照 |
| 欠損補完の上限 | 本バッチには定義されていない |

月次/年次へ集計される機器種別の一覧はより大きな集合であり、ガス総量/給湯/暖房および `POWER_CONSUMPTION` も含まれる ― これらは他のバッチに由来するものであり、本ドキュメントの対象範囲外である。
