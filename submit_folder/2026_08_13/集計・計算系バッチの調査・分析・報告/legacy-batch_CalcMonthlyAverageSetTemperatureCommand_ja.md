# 旧バッチ ― CalcMonthlyAverageSetTemperatureCommand（月毎平均設定温度算出）

## 概要

`CalcMonthlyAverageSetTemperatureCommand`は、旧システム（EMINEL コンシェルジュサーバー）において**1日1回、暖房シーズン中のみ（おおよそ12/1〜3/31）**実行されるバッチである。実行のたびに、**ちょうど1日分の環境センサー機器状態レコード全件**（読み取り回数は複数、部屋・機器を区別しない）を、世帯ごとに**1つの平均値**へ集約する ― その日の平均設定温度を表す値である。バッチはDBの読み書きのみを行い（メール送信・ファイル出力なし）、結果は`s_103`テーブルに書き込まれる。バッチ名に「月毎/Monthly」とあるのは、書き込み先テーブルが1行＝1世帯×1ヶ月×31日カラムという構成になっているためであり、これは**保存**の単位である。本バッチの**計算**の単位は1日である（実行のたびに、ちょうど1つの日カラムのみを計算・書き込みする）。実行スケジュール、クエリ文、計算式、およびこの結果を再利用する各バッチについては第2部で述べる。

## 第1部 ― 全体概要

| 項目 | 内容 |
|---|---|
| **役割** | 1日の間に発生した環境センサー機器状態レコード（0F45クラス）全件を（多→一に）集約し、世帯・日ごとに1つの平均設定温度値とすることで、月次集計バッチおよび設定温度の使用行動に基づくポイント付与機能「エコ暖房」の元データとする。 |
| **Input** | DBの読み取りのみで、**外部API呼び出しなし、CSVファイル読み込みなし**：`t_101`（世帯一覧）＋`t_202`（機器状態の生データレコード。既に別システムによって事前にingestされたもの ― `c219`カラムに設定値の生データが格納されている）。 |
| **Output** | **DB書き込みのみ** ― 実行のたびに、データが存在する各世帯について、`s_103`（entity `ConSensorDailyValue`、共通ライブラリ`EminelSvLib`経由）の**1行**の中の**1日カラム**を書き込み/更新する。メール送信なし、CSV出力なし。 |
| **処理概要** | 1. 「計算対象日」を決定する（デフォルト＝当日−1日）。そこから`[当該日 00:00, 翌日 00:00)`の範囲を導出する。<br>2. 論理削除されていない世帯を全件取得する（`t_101`）。<br>3. 各世帯について：`t_202`をクエリし、その日の範囲に該当する0F45クラスの機器状態レコード（レコード種別EA/EB）を全て取得し、時刻順に並べる。<br>4. 各レコードについて：`c219`カラムから2文字を切り出し、16進数→10進数に変換する。1日分の値全てを算術平均で集約し、10で除算する。<br>5. 平均値（レコードが1件以上ある場合）を、`s_103`の該当する月の行の、対応する日カラムに書き込む。すべて1つのトランザクション内で行う。その日にレコードが1件もない世帯には何も書き込まない（その日にnullレコードを作ることはしない）。 |

## 第2部 ― 詳細

### 2.1 実行スケジュールと計算対象時点

| 項目 | 内容 | 出典 |
|---|---|---|
| 実行スケジュール（cron） | 設定は3行で、いずれも**15:10**に`10_CalcMonthlyAverageSetTemperature.sh`を実行：`10 15 2-31 12 * *`（12月は1日を除く毎日）、`10 15 * 1,2,3 *`（1月/2月/3月は毎日）、`10 15 1 4 *`（4月1日のみ） | `docs/02_詳細設計/10_バッチ処理/mng-webap_cron設定_20241029.txt:30-33` |
| 実行コマンド | `php cake.php CalcMonthlyAverageSetTemperature [算出年月日]`（パラメータ`--date`、任意） | `CalcMonthlyAverageSetTemperatureCommand.php:24,38-42` |
| 計算対象日（`--date`未指定の場合） | `当日 − THIS_MONTH_CORRECTION_DATE（1日）` = **前日** | `CalcMonthlyAverageSetTemperatureCommand.php:62-66`, `const.php:593` |
| データ範囲 | `[計算対象日 00:00:00, 計算対象日+1 00:00:00)` | `CalcMonthlyAverageSetTemperatureCommand.php:69-72` |
| 結果の書き込み | 世帯・日ごとに1つの平均値を`s_103`に書き込む | — |

**cronのスケジュールがシンプルな1行ではなく3行に分かれている理由：** 「計算対象日」は実行日より常に1日遅れるため、暖房シーズン（12/1〜3/31）を過不足なくカバーするには、実行スケジュールは12/2〜4/1でなければならない ― 日数の異なる複数の月にまたがる期間は、標準的なcron式1つでは表現できないため、3行に分割する必要がある（12月は2日から、1〜3月は全日、そして4月1日のみを別行にする）。

### 2.2 データ取得クエリ

各世帯ごとに（順次ループ処理であり、全世帯をまとめる1本のSQLではない）：

```php
$deviceStatus = $deviceStatuses->find()
    ->select(['ems_sp' => c001, 'record_type' => c003, 'record_time' => c004, 'dev_epccf' => c219])
    ->where([
        c001 => $emsSp,
        c004 . ' >=' => $periodFrom,      // 00:00:00 ngày tính
        c004 . ' <' => $periodTo,         // 00:00:00 ngày kế tiếp
        c003 . ' IN' => ['EA', 'EB'],
    ])
    ->andWhere(fn($exp) => $exp->between(c006, '0F4500', '0F45FF'))
    ->order(c004)
    ->all();
```
出典：`CalcMonthlyAverageSetTemperatureCommand.php:102-121`。

**クエリで使用するカラムの意味：**

| テーブル | カラム | 意味 | 備考 |
|---|---|---|---|
| `t_101` | `c001` | 世帯コード（EMS-SP） | 各世帯を順次処理 |
| `t_101` | `c052` | 論理削除日時 | `IS NULL` ＝ 有効な世帯 |
| `t_202` | `c001` | 世帯コード | 絞り込み条件 |
| `t_202` | `c003` | レコード種別 | `'EA'`/`'EB'`で絞り込み |
| `t_202` | `c004` | 受信日時 | 日の範囲で絞り込み、`ORDER BY` |
| `t_202` | `c006` | 機器クラスコード（EOJ） | `0F4500`〜`0F45FF`で絞り込み（環境センサークラス ― バッチ`CalcTenMinutesSensorCommand`と同じ機器クラス） |
| `t_202` | `c219` | プロパティ生データ（EPC `CF`） | ⭐ 設定温度の算出に使用する値 |

1日あたりのレコード件数に制限はない ― 機器が1日に複数回データを送信する場合（複数の時刻、また子機器コードで絞り込んでいないため同一世帯の複数機器の可能性もある）、**すべて**が1つの平均値の計算に含められる。

### 2.3 計算式（世帯ごと、1日分を集約）

```
その日の各レコードについて：
    ① dev_epccf（c219）文字列のオフセット2の位置から2文字を取得する：substr(dev_epccf, 2, 2)
    ② 16進数→10進数に変換し、世帯の値配列に追加する

その日のレコードを全て処理した後（配列に1件以上の要素がある場合）：
    平均 = 配列の合計 / 配列の要素数
    平均 = 平均 / 10
```
出典：`CalcMonthlyAverageSetTemperatureCommand.php:136-143`（`array_sum`、`hexdec`、`substr`）。

特殊値／有効範囲外の値を除外するステップは存在しない（`CalcTenMinutesSensorCommand`の計算式とは異なる点）― クエリ条件に合致するレコードは全てそのまま平均計算に含められる。その日にクエリ条件に合致するレコードが1件もない世帯については、計算・書き込み処理は実行されない（その世帯はその日についてはスキップされる）。

### 2.4 結果の書き込み ― 書き込み先テーブル`s_103`

- Entity：`ConSensorDailyValue`（共通ライブラリ`EminelSvLib`）、物理テーブル`s_103` ― 1行＝1世帯×1ヶ月、31の日カラム（`c011`〜`c041`）。
- 実行のたびに、データが存在する各世帯について：`device_type = ROOM_TEMP_SETTING (17)`、`room_id = 0`、`datetime` ＝「計算対象日」が属する月の01日（月行のキーとして使用）を設定し、平均値を対応する日カラム（`c0` + (その日の日数 + 10)）に設定した上で、`c051`（更新日時）を更新する。
- すべてバッチ全体で**1つのトランザクション**内にある：いずれかの世帯で書き込みが失敗した場合 → 全体を`rollback()`し`abort()`する。
- 世帯一覧の取得、または1世帯の機器データ取得でエラーが発生した場合 → バッチは`commit()`を呼び出し（rollbackはしない）、直ちに`abort()`して残りの世帯の処理を停止する ― これは結果書き込み時のエラー分岐（`rollback()`を使用）とは異なる。

出典：`CalcMonthlyAverageSetTemperatureCommand.php:165-193`、`ConSensorDailyValue.php:59-100`、`ConSensorDailyValuesTable.php:41`。

### 2.5 集計チェーンと結果を使用する機能

このバッチは設定温度集計チェーンの最初の連結点であり、同時に結果は1つのAPIによって直接読み取られる：

```

   ▼

   │  データがある日数 ≥                                 │
   │  （その月の日数 − NOT_SUMMARY_DATE_COUNT=10）の      │
```

本バッチと同じ命名の理由：`CalcYearlyPresetTemperatureCommand`は名前に「Yearly」とあるが、実行のたびに集約するのは**1ヶ月分**のデータのみ（複数の日カラム→1つの月カラム）であり、年行の1つの月カラムにのみ書き込む ― 保存単位は年だが、計算単位は月のままである。
