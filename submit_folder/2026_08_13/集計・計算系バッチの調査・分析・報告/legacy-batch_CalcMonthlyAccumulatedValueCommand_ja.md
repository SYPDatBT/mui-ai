# 旧バッチ ― CalcMonthlyAccumulatedValueCommand（月毎積算値データ算出機能）

## 概要

`CalcMonthlyAccumulatedValueCommand` は、旧システム（EMINEL コンシェルジュサーバー）において**1日1回**実行されるバッチである（名称に「Monthly」とあるが実際は日次実行）。実行のたびに、`s_102` に既に存在する**1日分**の24時間カラムを合計し、その値を `s_103` の該当する月次行の1つの日カラムに書き込む — 対象は11種類の指標（ガス、電気、蓄電池、温度操作など）。クラス名に「Monthly／月毎」とあるのは、書き込み先テーブル `s_103` が1行＝1か月×31日カラムという構造で保存されるためであり、これはあくまで保存単位であって、1回の実行における集計単位は「日」である。

当日分の書き込みに加えて、バッチは `s_103` 内で最大1か月前まで遡って値が空（NULL）になっている日を自動検出し、`s_102` から再計算して補完する。バッチはDBの読み書きのみを行い、外部APIの呼び出し、CSVの読み込み・出力、メール送信は行わない。なお `POWER_CONSUMPTION` タイプに限っては、月次集計を行う前に、別バッチ（`CalcDailyEnergyConsumptionCommand`）の関数を呼び出し、直近7日分の時間値を再計算する。詳細は第2部を参照。

## 第1部 ― 総論

| 項目 | 内容 |
|---|---|
| **役割** | `s_102` に存在する1日分の24時間カラムを合計して1日分の値とし、`s_103` の月次行にある該当する日カラムへ書き込む処理を、11種類の指標（ガス総合／ガス給湯／ガス暖房／消費電力／ガス発電／太陽光／買電／売電／蓄電池放電／蓄電池充電／温度操作）について行う。あわせて、直近1か月以内で漏れている日を検出し補完する。 |
| **入力** | DBの読み取りのみで、**外部API呼び出し・CSV読み込みは行わない**：`t_101`（世帯一覧）＋ `s_102`（時間ごとの合計、1日24カラム、他の時間／日次バッチが事前に書き込み済み）＋ `s_103`（既存の月次行、NULLの日カラムを検出するために使用）。 |
| **出力** | **DBへの書き込みのみ** — 実行1回につき指標ごとに1つの日カラムを `s_103` へupsertする；再計算の仕組みが作動した場合は、複数の日カラム（前月の行を含む）に追加で上書きすることがある；再計算に使用した `s_102` の時間行に対して `c009` フラグを更新する。メール送信・CSV出力は行わない。 |
| **処理概要** | 1. `--type`（必須）と `--date`（任意、デフォルト＝前日）を読み込み、バリデーションを行う。<br>2. `type = POWER_CONSUMPTION` の場合：`CalcDailyEnergyConsumptionCommand` の時間再計算関数を呼び出し、直近168時間（7日分）を再計算する。<br>3. 有効な各世帯について：`s_102` の「対象日」の24時間カラムを合計し、`s_103` の月次行にある1つの日カラムへupsertする。<br>4. 当月の月次行が既に存在する各世帯について：日を1つずつ遡り（最大1か月前まで）、`s_103` の中で直近のNULLの日を探す。<br>5. 見つかった欠損期間について `s_102` から日次合計を再計算し、該当する日カラムへ上書きする（前月の行にまたがることもある）。その後、関連する `s_102` の時間行に集計済みフラグを付ける。 |

## 第2部 ― 詳細

### 2.1 実行スケジュールとパラメータ

| 項目 | 内容 |
|---|---|
| 実行スケジュール（cron） | `20 3 * * *` ― 1日1回、午前3時20分 |
| 実行コマンド | `php cake.php CalcMonthlyAccumulatedValue --type=<...> [--date=<...>]` |
| `--type` | 必須 ― カンマ区切りで複数指定可、各値は `AGGREGATION_TYPE_MONTHLY`（11種類、2.2参照）に含まれている必要がある |
| `--date` のデフォルト | 現在日 − 1日 |
| `--date` を手動指定する場合 | フォーマットは `yyyy-MM-dd` |
| 対象カラム | `c%03d` ＝ 日＋10 → 例：1日 → `c011`、31日 → `c041` |

このコマンドのdocblockには、有効な `--type` 値として `7:灯油消費量`（灯油）も記載されているが、定数 `7` は `AGGREGATION_TYPE_MONTHLY` には存在しない — `--type=7` を指定した場合、バッチはステップ1のバリデーションでエラーになる。

### 2.2 月次集計の11種類の指標（`AGGREGATION_TYPE_MONTHLY`）

| `type` | 業務名称 | 説明 |
|---|---|---|
| `GAS_CO_TYPE_CONSUMPTION` (2) | ガス総合消費量 | 世帯のガス消費量の合計（暖房＋給湯＋その他の合計） |
| `GAS_WATER_HEAT_RATE` (3) | ガス給湯消費量 | 給湯に使用したガス量 |
| `GAS_HEAT_CONSUMPTION` (4) | ガス暖房消費量 | 暖房に使用したガス量 |
| `POWER_CONSUMPTION` (5) | 消費電力量 | 世帯の消費電力量の合計 ― 集計前に専用の時間再計算ステップがある（2.4参照） |
| `GAS_POWER` (8) | ガス発電電力量 | ガスで動く発電機（コージェネレーション）が発電した電力量 |
| `SOLAR_GENERATION` (9) | 太陽光発電電力量 | 太陽光パネルが発電した電力量 |
| `SALE_ELECTRIC` (10) | 売電量 | 系統へ売却した電力量 |
| `BUY_ELECTRIC` (11) | 買電量 | 系統から購入した電力量 |
| `BATTERY_DISCHARGE` (12) | 蓄電池(放電量) | 蓄電池から放電された電力量 |
| `BATTERY_CHARGE` (13) | 蓄電池(充電量) | 蓄電池に充電された電力量 |
| `ROOM_TEMP_ADJUST_CNT` (15) | 室温設定の操作回数 | ユーザーが室温設定を操作した回数 |

`DETECT_CNT`（人感、14）はこのリストに含まれていない — 人感は日単位（`s_102`）にとどまり、月次への集計は行われない。これは `legacy-batch_CalcDailyAccumulatedValueCommand.md` の記載内容と一致する。

### 2.3 `s_102` からの日次合計取得と `s_103` への日カラム書き込み

`type` ごとに、関数 `getAggregateValue` は1つのSQLを実行する：`t_101`（論理削除されていない世帯を絞り込み）と `s_102`（`type` が一致し、`room_id = DETECT_LIVING(0)`、日付 = `--date` で絞り込み）を結合し、24個の時間カラム（`c011`〜`c034`、NULLは0として扱う）を合計して1つの `TOTAL` カラムとする。あわせて世帯の5つの属性グループ（`c012, c042, c015, c016, c024`）も取得する。

`room_id` は `type` に関わらず `DETECT_LIVING(0)` に固定して絞り込まれる — `room_id` が0以外になるのは `DETECT_CNT`（月次リストには含まれない）のみであるため、残り11種類の指標についてはこの条件は常に成立する。

結果の各行について、関数 `updateMonthlySensorInfo` は新しい `ConSensorDailyValue` エンティティを作成する ― キーは（世帯コード、種別、room=0、当月1日）― フラグ `c009 = 1`（集計要）をセットし、5つの属性グループをコピーし、該当する日カラム（`--date` から算出される `columnName`）に `TOTAL` をセットしたうえで、主キーに基づき `save()`（upsert）する ― 既存行を読み出して修正するのではなく、常に新しいエンティティを作成して保存する点は、`CalcDailyAccumulatedValueCommand` が `s_102` に書き込む方式と同じである。

### 2.4 `POWER_CONSUMPTION` 専用のステップ

`POWER_CONSUMPTION`（5）の月次集計を行う前に、バッチは `CalcDailyEnergyConsumptionCommand` のインスタンスを1つ生成し、そのバッチの関数 `calcPowerConsumption(対象日 23:00, 168)` を直接呼び出す ― これにより、2.3の日次合計への集計を行う前に、直近最大168時間（7日分）の時間値（`s_102`）を再計算する。`calcPowerConsumption` の計算式の詳細は、別ドキュメント `legacy-batch_CalcDailyEnergyConsumption.md` を参照。

### 2.5 前日以前のNULL検出時の再計算（`recalculation`）

ステップ2.3の後、`type` ごとにバッチは続けて再計算の仕組みを実行する：

```text
1. getRecountEmssp: s_103 に現在の月次行が既に存在する（世帯, type, room=0）
   の一覧を取得し、t_101 と結合して論理削除されていない世帯を絞り込む。
2. 各世帯について: getRecountDateTime が（対象日 − 2日）を起点として
   日を1つずつ遡り、最大1か月前まで探索する:
   - s_103 内で値が入っている（NULLでない）日に到達した場合
     → 再計算の開始点 ＝ その日の翌日、探索を終了
   - 1か月遡っても値のある日に到達しなかった場合
     → 再計算の開始点 ＝ 1か月前の時点、探索を終了
3. createUpdateData: [開始点, 対象日 − 1日] の範囲について、s_102 から
   日次合計を再計算する。
4. updateDailySensorRecalculation: 算出した各日次合計を、s_103 の該当する
   月次行の日カラムへ書き込む（UPDATEのみ、新規行は作成しない）―
   再計算の範囲が2か月にまたがる場合は、月次行ごとに分けて書き込む；
   当月以外の月次行については、その月次行自体にフラグ c009 = 1
   （再集計要）を追加でセットする。
5. updateRetroactiveFlag: 今回再計算した範囲内の s_102 の時間行のうち、
   c009 = 1（集計待ち）になっている行に限り、フラグを c009 = 2
   （集計済み）に更新する。ステップ4〜5は世帯単位で1つのトランザクション
   内で行われる。
```

この仕組みのどのステップにおいても、集計値そのものの妥当性（正負・閾値など）はチェックされない ― チェックされるのはNULLかどうかのみである。

### 2.6 関連する `s_103` のフィールド

| フィールド | 意味 | セットされるタイミング |
|---|---|---|
| `c001`~`c004` | 主キー（世帯コード、機器種別、位置、月） | 書き込みのたびに |
| `c009` | 集計要フラグ（年次集計／再計算用） | 新しい日カラムを書き込むとき（2.3）に `= 1`、または再計算が当月以外の月次行に及んだとき（2.5）に `= 1` |
| `c111`~`c115` | 5つの属性グループ：住宅種別、暖房能力、床面積、居住人数、コージェネレーション種別 | 世帯一覧から各行へコピー |
| `c011`~`c041` | 日ごとの値を格納する31カラム（01日〜31日） | 実行1回につき1カラム、再計算時は複数カラム |

### 2.7 関連する業務定数

| 定数 | 値 |
|---|---|
| `AGGREGATION_TYPE_MONTHLY` | `[2, 3, 4, 5, 8, 9, 10, 11, 12, 13, 15]` ― 業務名称は2.2を参照 |
| `DETECT_LIVING` | `0` ― このバッチで絞り込み・書き込みに使用する固定の room_id |
| 再計算時の遡り上限 | `--date` の最大1か月前まで |
| `POWER_CONSUMPTION` 専用の時間再計算の上限 | 168時間（7日分） |

### 2.8 集計の連鎖

本バッチは、`CalcDailyAccumulatedValueCommand` のドキュメントで述べた「1行、時間単位のNカラム」という連鎖の2番目の環である：

```
s_102  "ConSensorHourlyValues"   1行/日   × 24時間カラム   (他の時間／日次バッチが書き込み)
   │  CalcMonthlyAccumulatedValueCommand  (☚ 本ドキュメントで分析しているバッチ ― 1日1回実行)
   ▼
s_103  "ConSensorDailyValues"    1行/月  × 31日カラム  (c011~c041)
   │  年次集計バッチ（1か月1回実行）
   ▼
s_104  "ConSensorMonthlyValues"  1行/年    × 12月カラム
```

`GAS_POWER/SOLAR_GENERATION/SALE_ELECTRIC/BUY_ELECTRIC/BATTERY_DISCHARGE/BATTERY_CHARGE` について `s_102` を書き込む元バッチは `CalcDailyAccumulatedValueCommand`；`POWER_CONSUMPTION` については `CalcDailyEnergyConsumptionCommand`（本バッチ内で直接呼び出される、2.4参照）；`GAS_CO_TYPE_CONSUMPTION/GAS_WATER_HEAT_RATE/GAS_HEAT_CONSUMPTION/ROOM_TEMP_ADJUST_CNT` については本ドキュメントの対象範囲外である。
